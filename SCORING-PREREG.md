# Scoring and case-selection pre-registration

**Registered:** 2026-07-26
**Applies to:** CELL-GENOMICS-D-26-00551, revision item N7 (Reviewer 2, point 5)
**Frozen pattern fingerprint:** `bfab39f4ebc5bd53aacf6b3805478af29eb0cb06042151fefaa8e3d85b626d94`

Reviewer 2 asked whether the clinical-equivalence scorer was widened after model
outputs were inspected. This document answers that directly, including where the
answer is unfavourable, and states what is frozen from this date forward.

## 1. What this registration does and does not claim

**It does not claim the equivalence patterns were pre-registered for the existing
dataset. They were not.** The patterns in `code/10b-rescore-v3-clinical-equivalence.py`
were written by inspecting model outputs from the v3 runs. The source file has said
so since it was written: *"every entry must be justified by an audited dry-run
example. Do not anticipate. Expand only after observed cases motivate the addition."*
That discipline was intended to stop the table over-generalising, and it did, but it
is data-motivated pattern development and the reviewer is right to name it.

Two consequences follow, and we accept both.

1. For the **existing** dataset, the equivalence-scored numbers are reported only
   alongside baseline-scored numbers. No claim in the paper rests on the equivalence
   layer alone. Where the two scorers disagree about a conclusion, the conclusion is
   withdrawn, not defended.
2. For **every new run** in this revision (N1 matched factorial, N4 drug-keyed
   retrieval, N5 cohort interpretation), the scorer is frozen *before* the run. That
   freeze is mechanical and checkable, not a promise: see section 4.

## 2. Case selection

usual sense.** The 110 cases are an exhaustive encoding of the CPIC Level A gene-drug
guideline tiers across 21 genes, generated by `code/07-generate-cases-v3.py` from the
published CPIC guideline tables. Every tier documented in the source guideline for an
included gene-drug pair became a case. Cases were not dropped, sampled or re-weighted

## 3. The two scorers

| | Baseline | Clinical-equivalence |
|---|---|---|
| Script | `code/10-rescore-v3.py` | `code/10b-rescore-v3-clinical-equivalence.py` |
| Status | locked, untouched | frozen at the fingerprint above |
| Role | primary | reported alongside, never alone |

**Stated property of the equivalence layer.** It only ever *promotes* a phenotype
score from below 1.0 to 1.0, when an equivalent phrase matches and its canonical tier
equals the target tier. It never demotes, so a 1 to 0 transition cannot occur and the
baseline score is a floor. This is no longer only a docstring claim: it is enforced by
`tests/test_scorer_freeze.py::test_equivalence_layer_only_promotes`.

**Stated limitation.** The layer promotes phenotype labels only. It does not touch
drug-recommendation scoring or lethal-class action scoring. Reporting both scorers
side by side is what neutralises the asymmetry, and STAR Methods will say so.

## 4. What the freeze mechanically prevents

The fingerprint is a SHA-256 over the semantic content of the three pattern tables:
regex text, canonical tier, and locus filter for every entry in `LOCUS_PATTERNS`,
`GENERIC_HLA_RISK_ALLELE_PATTERNS` and `CLINICAL_EQUIVALENCE`, plus the
`HLA_RISK_ALLELE_GENES` set. Comments and formatting are excluded, so reformatting
cannot look like tampering, and changing what a pattern *means* cannot slip through.

```bash
python code/10b-rescore-v3-clinical-equivalence.py --fingerprint   # print live hash
python code/10b-rescore-v3-clinical-equivalence.py --frozen ...    # refuse if it moved
```

`--frozen` exits non-zero and scores nothing if the live fingerprint differs from the
registered one. Every scoring run reported in the revision is invoked with `--frozen`.
`tests/test_scorer_freeze.py` fails on any unregistered change, so the freeze is
enforced in CI as well as at the command line.

## 5. Procedure for changing a pattern after this date

Widening the table is not forbidden, but it must be visible and dated. The procedure:

1. Add a dated entry to the changelog below stating what changed, why, and which
   observed outputs motivated it.
2. Update `FROZEN_PATTERN_SHA256` to the new fingerprint.
3. Re-report every affected number under both scorers, before and after the change.

A change that cannot survive step 3 is a change that was tuning the ruler to the
result, and should not be made.

## 6. Model-set inclusion criterion (registered 2026-07-26)

Headline numbers are reported on the **eight-model common set**. Mistral is
reported separately as a paced sensitivity check. The criterion is stated here
rather than applied silently, because dropping a model after seeing its results
is the same post-hoc selection this document exists to prevent.

A model is excluded from the primary analysis if **any** of the following holds.
All three are properties of provenance or infrastructure, none is a property of
the model's scores, and each could have been written down before a single result
was seen.

1. **The served version is unrecoverable.** The original run called
   `mistral-large-latest`, a moving pointer, so the model version that produced
   those evaluations was never recorded. This fails the reproducibility standard
   the paper itself sets.
2. **The specific version no longer exists.** `mistral-large-2411` has been
   withdrawn by the vendor. A rerun necessarily uses `mistral-large-2512`, a
   different model, so pooling the two would be the error.
3. **The request cadence is not comparable.** On the API tier available to us,
   Mistral returns HTTP 429 under the concurrency every other model tolerates:
   447 of 462 calls failed at full concurrency, 19.6% at 3 s spacing, 2.4% at
   8 s. Any figure computed for it under those conditions reflects our rate
   limit, not the model.

Criterion 3 also applies prospectively: if another provider begins rate-limiting
at a cadence the rest of the panel tolerates, it moves to the sensitivity set on
the same grounds.

The two retired Anthropic models are a separate matter and are handled by
same-tier substitution (Opus 4.5, Sonnet 4.5) with the substitution stated, not
by exclusion.
