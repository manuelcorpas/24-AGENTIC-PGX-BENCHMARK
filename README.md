# Agentic pharmacogenomics benchmark

Analysis code and derived data for **CELL-GENOMICS-D-26-00551**, "Trustworthy
agentic genomics requires validated skills, not better models".

## The current design: a matched five-cell comparison

**Read this section before any other file in the repository.** The revision uses
a matched five-cell comparison. It is not a complete factorial, because there is
no executable decision mechanism when no external knowledge is supplied and
retrieved prose is not converted into executable rules. `data/MANIFEST.md` maps
the submitted tables and figures to their authoritative inputs and generators.

The primary analysis crosses two factors:

- **knowledge representation**: none, retrieved CPIC guideline prose, or
  validated structured rules
- **decision mechanism**: the model generates the answer, or code executes the
  mapping

The five cells are free generation, RAG generation, RAG-assisted diplotype
calling followed by authored execution, authored-rule generation, and
authored-rule execution. Both execution cells run the same authored mapping;
retrieved prose is used only while the model chooses a diplotype and is not
itself executed. The answer-supplied condition is a historical parser and
infrastructure control, not a substantive cell.

Every cell receives identical patient text, names the same target drug, emits one
output schema, and is scored by a single function that is not told which cell
produced the row.

**110 CPIC Level A cases x 8 models common to all cells x 3 replicates =
2,640 attempted evaluations per cell and 13,200 attempted overall.** Exactly
13,199 records returned. The absent authored-rule-execution record is retained
as a failed attempt in end-to-end denominators rather than dropped. A single
clinical framing is used, so the three population framings of the original
design are not crossed into this grid.

Per-cell provenance, including the API identifier issued for each model and the
spend per cell, is regenerated by `python code/69-cell-provenance.py`. All five
cells were issued live against the same eight-model panel.

## Historical design (original submission)

The original submission reported a five-condition constraint gradient over nine
models and three ancestry framings, 44,550 evaluations. Those runners and data
remain in the repository and are still cited for the adversarial specification
test and the real-genome arm. They are not the primary analysis, and the
superseded scorings are separated into `data/SUPERSEDED/` with an explanation.

## Repository layout

```
code/      analysis pipeline: runners (all 5 conditions), rescorers, RAG,
           adversarial, chunking, five-condition aggregation, numbers engine, figures
specs/     benchmark inputs: test_cases_v3.json, cpic_rag_corpus_v3.json, concordance_spec.md
figures/   publication figures (PNG 300 dpi + TIFF 600 dpi)
data/      see data/README.md - datasets are archived on Zenodo, not in git
real-genome-arm/  three-population real-diplotype pipeline (PyPGx GRCh37)
```

### Key scripts (`code/`)

Core three conditions and scoring:
- `02-run-benchmark-v3.py`: free-prompted (`no_spec`) and answer-supplied (`with_spec`)
- `15-build-cpic-rag-corpus.py` + `16-run-rag-condition.py`: retrieval-augmented (`cpic_rag`)
- `16b-rag-genedrug-chunking.py`: (gene, drug)-keyed chunking control
- `14-adversarial-scrambled-spec.py` + `14b-adversarial-reverse-spec.py`: bidirectional adversarial
- `10-rescore-v3.py` + `10b-rescore-v3-clinical-equivalence.py`: scoring (baseline + clinical-equivalence layer)

Authored-rule conditions, added in the revision:
- `41-armA9-armBv2.py`: nine-model skill-reasoning (Arm A) and skill-execution (Arm B, controlled vocabulary); defines the model adapters, skill rules and prompt templates reused downstream
- `43-armAB-fullgrid.py`: the definitive skill-arm run on the identical 9-model x 3-pop x 3-rep x 110-case grid = **17,820** calls
- `40-`, `42-`, `42b-`, `41b-`, `41c-`: skill-arm prototypes, population sweep and model re-run helpers

Matched analysis, validation and figures:
- `60-matched-factorial.py`: matched five-cell runner
- `61-rescore-matched.py`: cell-blind scoring and per-cell report
- `65-hierarchical-stats.py`: clustered intervals and variance components
- `69-cell-provenance.py`: per-cell model identifiers, tokens and costs
- `70-figures-revision.py`: matched result, error-localisation, model-spread and cohort-coverage figures
- `72-validate-v30-numbers.py`: registered-number validator, updated for C14/C15
- `78-figure-input-normalisation.py`: seven-model Figure 8 from the frozen analysis
- `79-reparse-normalisation.py`: idempotent C14/C15 reparse of stored response text
- `80-figure6-adversarial-contract.py`: bidirectional corrupted-contract Figure 6
- `81-validate-submission-package.py`: cross-document and embedded-figure release gate
- `82-figure7-real-genome.py`: four-cohort real-genome Figure 7 under the manuscript's baseline scorer
- `83-freeze-seven-model-normalisation.py`: source hashes, paired cohorts and
  sample-cluster intervals for the seven-model input-normalisation analysis

## Data

Datasets are archived on Zenodo rather than stored in git; see `data/README.md`.
- **Curated benchmark dataset** (no individual genotypes): DOI 10.5281/zenodo.20567742
- **Synchronized corrected revision dataset**: DOI 10.5281/zenodo.21736175,
  paired with immutable repository tag `cg-revision-2026-08-01`.
- **Previous revision dataset**: DOI 10.5281/zenodo.21710394. This historical
  version predates corrections C14/C15 and must not be cited as the data
  snapshot supporting the corrected seven-model input-normalisation results.
- `code/76-stage-zenodo-revision.py` stages the corrected raw and derived files
  for the synchronized Zenodo version, including both directions of the
  adversarial test and the tagged source archive.

## Reproducing the analysis

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # add your own API keys
# download the Zenodo datasets into data/, then:
python code/61-rescore-matched.py --input data/v3_five_cell_live.json
python code/65-hierarchical-stats.py --input data/v3_five_cell_live_rows.json
python code/70-figures-revision.py
python code/79-reparse-normalisation.py
python code/83-freeze-seven-model-normalisation.py
python code/78-figure-input-normalisation.py
python code/80-figure6-adversarial-contract.py
python code/82-figure7-real-genome.py
python code/72-validate-v30-numbers.py --manuscript /path/to/final-manuscript.docx
python code/81-validate-submission-package.py --package-dir /path/to/submission-package
```

Re-running the benchmark from scratch (the `*-run-*` and `4*-arm*` scripts) issues live
API calls and incurs cost; the locked outputs on Zenodo let you reproduce every figure
and statistic without re-querying the models.
